# Android readiness

- Android CI (`android-apk.yml`) was the first real Android build; the app was never Android-ready (`SKIP_NO_ANDROID=1`). Each CI run exposes the next Apple-only layer.
- Fixed: `skip checkup` removed; `skip export --android --no-ios --release`; `skip-firebase` 0.21.0+ (Swift 6.4 `SkipFirebaseCore` link fix) which needs `firebase-ios-sdk` 12.19.2; `ApoorvaServices` imports `SkipFirebase*` (re-exports Firebase on Apple); `FirestoreCoding.swift` aliases `Firestore.Encoder/Decoder` on Android.
- Blank screen on device (2026-11-26): the APK launches but shows only the theme background. A probe `Text` in the app module's `ApoorvaRootView` renders, but `MainView` (in `ApoorvaAppCore`) renders nothing, not even a plain `Text` in its body. Cause: skip-fuse-ui renders a view through `Java_viewOrEmpty` (`(self as? SkipUIBridging)?.Java_view ?? SkipUI.EmptyView()`). The `skipstone` plugin generates `SkipUIBridging` conformance and Kotlin peers for custom views (skipstone `KotlinBridgeToKotlinVisitor`, `case .view`), but only in modules that use the plugin. The plain-package `SkipFuseUI` shim compiles but every custom view from those modules renders as `EmptyView`. Fix: each module with custom SwiftUI views (`ApoorvaAppCore`, `ApoorvaModules`, `ManiSwiftUIComponents`, `ManiLogger`) needs to be a Skip Fuse module (skipstone plugin plus `Skip/skip.yml` with `mode: 'native'`). Not R8: the debug (no R8) build is equally blank.
- Skip Fuse module recipe (2026-11-27; applied to `ApoorvaAppCore`, `ApoorvaModules`, ManiSwiftUIComponents and ManiLogger; the splash screen renders and Get started opens sign-in on device):
  - `Package.swift`: add `.package(url: "https://github.com/skiptools/skip.git", from: "1.9.13")` and `plugins: [.plugin(name: "skipstone", package: "skip")]`. Make `SkipFuseUI` unconditional: with `.when(platforms: [.android])` the generated Kotlin fails with `Unresolved reference 'bridge'`, because skipstone resolves Kotlin deps on the host.
  - `Sources/<Module>/Skip/skip.yml` with `skip: mode: 'native'`.
  - Views, view modifiers and their `@State`/`@Environment`/`@Binding`/`@Bindable`/`@FocusState`/`@AppStorage` properties can't be `private` ("Private views cannot be bridged to Android"). Types those properties use can't be private either.
  - Every file with an `@Observable` class needs `import SkipFuse`. It re-exports SkipAndroidBridge's `Observation.ObservationRegistrar`, which notifies Compose. Without it state changes (e.g. `NavigationStack` path pushes) never redraw.
  - No `Bundle.main` / `UserDefaults.standard` in default arguments ("SkipAndroidBridge was not imported by this file"): take an optional and resolve it in the body.
  - `UserDefaults` in a Skip module is an internal bridge type (`SkipAndroidBridge.AndroidUserDefaults`), so it can't appear in a `public` signature; keep the injectable init internal.
  - `removePersistentDomain` is unavailable; `View.bold()` doesn't exist (only `Text.bold()` / `Font.bold()`).
- Device run 2026-11-27, after sign-in:
  - "database is locked" (SQLite 5) during sync, plus 3+ parallel Remote Config fetches at launch. Cause: `MainView`'s `@State var coordinator = AppCoordinator()` re-ran its initializer every time `MainView` was re-created, and each `AppContainer` opened its own connection and started its own sync. Fix: one process-wide `RootCoordinator.instance` (`MainView.swift`). Home's "Offline" label means sync failures (`HomeCoordinatorView.refreshSyncText`), so it follows from the same bug.
  - Warning triangles in place of icons: Skip only maps about 65 SF Symbol names to Material icons (skip-ui README, "System Symbols"). `ManiSymbol.name(_:)` (ManiSwiftUIComponents) swaps any other name for the closest mapped one on Android and is a no-op on Apple. Use it for every `systemName:`/`systemImage:`. A faithful alternative is SVG exports named after the symbol in the app module's `Module.xcassets`.
  - Debug test user `lavanya@gmail.com` got "credential incorrect": the account doesn't exist. Removed from `DebugTestUsers`; `LoginViewModel` now prefills the first entry there (`manikantanandam1996@gmail.com`) instead of a hard-coded email. Errors showed as raw `SwiftJNI.ThrowableError error 1`: `AuthService.mapped` only matched iOS `AuthErrorDomain` codes, and splitting the description on "Exception: " in `UserFacingError` didn't help. `AuthService.androidMapped` now matches Firebase exception class names and messages in the error's description and logs the raw description (category auth) for new cases.
  - Brown surfaces (Settings, Developer, Logs, the area behind the tab bar) and pink large titles: Skip applies Material 3 dynamic (wallpaper) colours by default. `Main.kt` wraps `PresentationRoot` in `Material3ColorScheme` with fixed colours from `ManiDefaultBaseTheme` (`apoorvaMaterialColors`). Accent themes other than the default don't reach Material yet.
  - Verified after the fixes: readable sign-in error, Settings without brown, Cashflow cash-out entry saved, new customer saved, bill #AT-1 back after sign-out and sign-in (Firestore sync works).
  - Phone fields showed a letter keyboard: `ManiInputField` gated `keyboardType` on `canImport(UIKit)`; SkipFuseUI has it, so it's now `canImport(UIKit) || os(Android)`. Verified: phone fields now get the number pad. The New bill button rode up over Save buttons when the keyboard opened; `.ignoresSafeArea(.keyboard)` didn't help (Android resizes the window), so on Android `HomeTabsCoordinatorView` shows it only on tab roots (`HomeTabsCoordinator.isAtTabRoot`). Inventory add item also verified; the + button now hides on pushed screens.
  - `manikantanandam1996@gmail.com` / `Apoorva@125` works on iOS but Android gets FIRAuthErrorDomain 17004 (invalid credential), while `nanirocks125@gmail.com` works on both. Suspect iOS and Android point at different Firebase projects (GoogleService-Info.plist vs google-services.json); not checked (config files are off-limits to Claude).
- Next blocker: `no such module 'SwiftUI'` in plain packages. `skip-fuse-ui` ships a `SwiftUI` shim target inside the `SkipFuseUI` product only when `TARGET_OS_ANDROID` is set, so SwiftUI-importing packages need `SkipFuseUI` as an Android-conditional dependency (no `skipstone` plugin needed). Unverified until CI.
- Affected: `ManiSwiftUIComponents`, `ManiLogger` (external repos, need releases), `ApoorvaModules`, `ApoorvaAppCore`.
- Apple-only imports to guard: `UIKit`/`CoreImage` (`ApoorvaColor`, `UPIQRView`), `VisionKit` (`POSExtraScreens`), `Combine` (`ReceiptView`, `AuthScreens`), `Security` (`PinStore`), `os` (`AppLogger`).
- Also check: `google-services` Gradle plugin and Firebase init on Android.
- Phases and verification: see the plan (SwiftUI shim, guards, runtime config, device smoke test, cleanup of the temporary PR trigger and diagnostics step).

## Android gates (iOS/Android differences)

Each `#if os(Android)` gate is a deliberate gap. Goal first is a building APK; revisit these after the first working one. Add a row whenever a new gate is introduced.

| Where | Gate | Android behaviour vs iOS | Possible proper fix |
|---|---|---|---|
| `ManiLogger` `UI/LogDetailView.swift` | `textSelection` | Log text can't be selected | Share sheet (already offered) or Skip text-selection support |
| `ManiLogger` `UI/LogDetailView.swift` | `AttributedString.backgroundColor` | Search match is bold only, no tint | Overlay/segmented `Text` runs |
| `ManiLogger` `UI/LogViewerView.swift` | `safeAreaInset` | Filter header scrolls with the list, not pinned | `VStack` layout with header above the list |
| `ManiLogger` `Core/AppLogger.swift` | `canImport(os)` | No `os.Logger` console output; registered `LogSinks` only | Android log sink (`android.util.Log` via Skip) |
| `ManiSwiftUIComponents` `Theme/AndroidCompat.swift` | `maniBorder` | Border stroked centred, not inset (about half a line-width) | Inset the shape by `lineWidth / 2` once SkipSwiftUI supports it |
| `ManiSwiftUIComponents` `Theme/AndroidCompat.swift` | `monospacedDigit` (Font, Text) | No-op; digits may not align in columns | Fixed-width font or SkipSwiftUI support |
| `ManiSwiftUIComponents` `Gallery/ManiComponentGallery.swift` | whole file excluded | Dev gallery absent | None needed (dev-only) |
| `ApoorvaServices` `Firestore/FirestoreCoding.swift` | `Firestore.Encoder` = own `AndroidFirestoreEncoder`; `Firestore.Decoder` alias + own `decode(_:from:)` | Same API; both go through JSON (dates as `Timestamp` when encoding, seconds when decoding). skip-firebase's `FirestoreEncoder.encode` passes the Swift value to Java and crashed with "Unable to bridge Swift instance OrgSettings" on the first write (Collect on checkout); native Swift can't see its reified `decode` | Revisit if skip-firebase bridges Codable values |
| `ApoorvaServices` `Firestore/FirestoreStoring.swift` | `setData` | skip-firebase's `setData` is async, so it runs in a `Task`; errors are logged, not thrown | Expose an async `setData` in `FirestoreStoring` |
| `ApoorvaServices` `Observability/FirebasePerformanceMonitoringService.swift` | `startTrace` | Uses `sharedInstance().trace(name:)` + `start()` | None (parity) |
| `ApoorvaServices` `AuthService/AuthService.swift` | `EmailAuthProviderID`, `AuthStateDidChangeListenerHandle` | Local constant `"password"` and typealias to `AuthStateListener` | None (parity) |
| `ApoorvaServices` `AuthService/AuthService.swift` | `mapped` → `androidMapped` | Friendly auth errors come from matching text in the Java exception's description, not error codes | Map `FirebaseAuthException.errorCode` once skip-firebase exposes it |
| `ApoorvaServices` `RemoteConfig/FirebaseRemoteConfigService.swift` | `setDefaults` | Defaults kept in memory (`AndroidRemoteConfigDefaults`) as strings and returned when Firebase reports a key as `.static`. Before this every `auth.*` flag read false and the sign-in hub showed no methods | Convert `[String: NSObject]` to `AnyDynamicObject` and call the SDK's `setDefaults` |

| `ApoorvaModules` `Inventory/InventoryView.swift`, `Onboarding/OpeningBalances.swift` | `fileImporter`, `UniformTypeIdentifiers` | CSV import can't pick a file | Android document picker |
| `ApoorvaModules` `Inventory/InventoryView.swift` | `ShareLink` + `SharePreview`, `editMode` | No template download; categories can't be drag-reordered | Android share intent; move up/down buttons |
| `ApoorvaModules` `Components/EverySecond.swift` | `.task` loop replaces `Timer.publish`/Combine | Same countdowns on both platforms | None (parity) |
| `ApoorvaModules` `Resources/ApoorvaColor.swift` | `canImport(UIKit)` | System background is plain white on Android (no dark mode) | Theme-based background |
| `ApoorvaModules` `Checkout/UPIQRView.swift` | `canImport(CoreImage)` | QR icon instead of a real UPI QR | Pure-Swift QR generator |
| `ApoorvaModules` `Components/ScreenKit.swift` | `safeAreaInset`, `FlowLayout` | Bottom bar stacked under scroll view; chips scroll sideways instead of wrapping | Custom wrapping layout |
| `ApoorvaModules` `Components/AndroidCompat.swift` | `Grid`/`GridRow`, `contentShape`, `monospacedDigit`, `appBorder` | Attendance grid columns don't align; empty areas of tappable rows aren't hit-testable; borders centred | Real grid via `LazyVGrid`; wait for SkipSwiftUI support |
| `ApoorvaModules` `Customers/CustomerScreens.swift`, `CustomersView.swift` | `ImageRenderer`, `ShareSheet`, `UIApplication.open` | Statement PDF/PNG export returns nothing; share sheets are empty; call button runs in a `Task` | Android share intents and PDF rendering |
| `ApoorvaModules` `POS/POSView.swift`, `Money/MoneyScreens.swift`, `Sell/SellScreens.swift` | `.graphical` date picker, `DatePicker(in:)` | Plain date picker; no min/max date | Enforce limits in view models |
| `ApoorvaModules` `Components/IconView.swift`, `ApoorvaAppCore` `MainView.swift` | `#Preview` | None (dev only) | None |
| `ApoorvaModules` `Developer/DeveloperSettingsViewModel.swift`, `ApoorvaAppCore` `UITestingConfig.swift` | `removePersistentDomain` | Environment switch and UI-test reset don't wipe UserDefaults | Remove known keys one by one |
| `ApoorvaModules` `Session/AppSession.swift`, `Components/Theme/ThemeStore.swift` | `UserDefaults` only in internal inits | None (public inits use `.standard`; tests inject via `@testable`) | None: in Skip modules `UserDefaults` is an internal bridge type (`AndroidUserDefaults`) and can't appear in public signatures |

Planned, not yet gated: `VisionKit` scanner (`POSExtraScreens`) and `Security` Keychain (`PinStore`). The local build succeeded without touching them, so they may already be guarded; check before shipping.

## Local build

`scripts/android-export.sh` runs the same export as CI (about 80s incremental, 19 min clean) and prints de-duplicated errors. Its first success produced a 478 MB `Apoorva-release.apk`; the size needs investigation (likely multiple ABIs and unstripped libraries). Local results only match CI when Skip and the SwiftPM packages resolve to CI's versions; clear `~/Library/Caches/org.swift.swiftpm` and `app/.build` if they drift.
