# Android CD

- Every push to `main` builds an Android APK via `.github/workflows/android-apk.yml` (macOS 15, Skip CLI). iOS is excluded (no developer account).
- Delivery: GitHub pre-release `android-<sha7>`, newest 10 kept; also a workflow artifact.
- Signing: release build, debug-signed (no `keystore.properties`; `build.gradle.kts` falls back to debug). Switch to a keystore secret before Play distribution.
- `SKIP_NO_ANDROID=1` stays in committed `app/Skip.env`; CI strips it on the runner only. `CURRENT_PROJECT_VERSION` = run number.
- Secrets (2026-11-20): `GOOGLE_SERVICE_JSON_DEBUG_B64` (project `apoorva-debug-8f9eb`) and `GOOGLE_SERVICE_JSON_PRODUCTION_B64` (`apoorva-production`), both package `com.apoorva.app`. The google-services Gradle plugin reads one `google-services.json`, so `scripts/setup-firebase-config.sh` writes the one chosen by `GOOGLE_SERVICE_JSON_ENV` (main-branch CI APKs always use `debug`; a separate custom workflow will build and deploy the production APK later; Android has no runtime env switch like iOS). The legacy `GOOGLE_SERVICE_JSON_B64` is still a fallback. The workflow fails if the debug secret is missing (2026-11-20): the run of `0f27a71` built without it and the APK crashed at launch ("crashed repeatedly") on a device.
- No `skip checkup` in CI (removed 2026-11-15): it builds/tests Skip's own hello-skip sample and failed on its Kotlin test (`HelloSkipTests.classMethod`, ~7.5 min), unrelated to this app. Only `skip android sdk install` runs.
- APK size (2026-11-16): the first APK was ~500 MB (arm64-v8a + armeabi-v7a + x86_64 native libs, ~150 MB each, `lib_FoundationICU.so` ~45 MB per ABI). CI now passes `--arch aarch64` to `skip export` (arm64 only, expect ~160 MB). Emulators (x86_64) and 32-bit devices are not supported by the CI APK.
- minSdk is 28 (Android 9+); a Lenovo TB-X304L on Android 8.1 cannot install it.
- Further size lever if needed: `keepDebugSymbols` in `app/Android/app/build.gradle.kts` keeps unstripped `.so` files.
- Launch crash root cause (2026-11-26): the APK installs fine via `adb install` (tested on a Redmi Note 10 Pro, Android 13, arm64, with `android-3551ba4`) but crashes at launch with `Default FirebaseApp is not initialized` (from `SkipFirebaseCrashlytics_Bridge.swift:40`). `app/Android/app/build.gradle.kts` never applied the `com.google.gms.google-services` plugin, so CI wrote `google-services.json` but no `google_app_id` resource ended up in the APK. Fix: apply that plugin (4.4.2) in the app `plugins {}` block. A missing json now fails the Gradle build instead of crashing at runtime. The next launch crash was `The Crashlytics build ID is missing`, fixed by also applying `com.google.firebase.crashlytics` (3.0.2). The Android Swift build also needed `accessibilityLabel(Text(...))` for non-literal `String` labels (SkipUI has no `String` overload). Third launch crash: `SkipSQL/SQLPlatform.swift:17: no platform SQLiteCLibrary available; use SkipSQLPlus instead`. On Android native, SkipSQL's `.platform` config calls `fatalError`. Linking `SkipSQLPlus` next to `SkipSQL` fails the Android build (`SkipFFI-product is linked as a static library by 'Apoorva-product' and 'SkipSQLPlus-product'`, because SkipSQLPlus is a dynamic product). So `ApoorvaOfflineStorage` depends only on `SkipSQLPlus` on every platform, imports `SkipSQLPlus`, and opens the DB with `.plus` (bundled SQLite on iOS too).
- Fourth crash: SIGTRAP in `SkipFirebaseRemoteConfig` `fetchAndActivate` (JNI method-ID lookup). The R8 release build renamed `kotlinx.coroutines.Job` (to `i1`) and `kotlin.coroutines.Continuation`, so Swift's JNI signature lookup failed. Fix: `proguard-rules.pro` keeps `kotlin.coroutines.**` and `kotlinx.coroutines.**`.
- Fifth crash: `SkipFirebaseRemoteConfig_Bridge.swift:432 ... [Value: 1.0.0] cannot be converted to a boolean`. `FirebaseRemoteConfigBackend.value(forKey:)` reads bool and number for every key. Firebase Android throws for non-convertible strings (iOS returns false/0), and Skip bridges the call with `try!`. On Android the adapter now derives bool and number from `stringValue`.
- After those five fixes the local release APK launches and stays running on the Redmi Note 10 Pro (2026-11-26).
- Local builds: `scripts/android-export.sh` takes ~22 min for all ABIs; `ARCH=aarch64 scripts/android-export.sh` builds arm64 only, like CI.
- Untested locally (no-build rule): first CI run may need tuning of Skip/SDK install steps or `skip export` flags.
